# LeetCode27\-移除元素

## 一、题目题意

给你一个数组 `nums` 和一个值 `val`，需要 **原地** 移除所有数值等于 `val` 的元素，并返回移除后数组的新长度。

要求：

- 不能使用额外数组空间，只能原地修改

- 数组前 k 个元素必须是保留的有效元素（顺序不限）

- k 为返回的新长度

## 二、我的错误思路（标记\+排序法）

### 1\. 错误代码

```Plain Text
class Solution {
public:
int removeElement(vector<int>& nums, int val) {
int i = nums.size(), j = 0;
int length = 0;
while (j < i)
{
if (nums[j] == val) nums[j] = 100;
else length++;
j++;
}
sort(nums.begin(), nums.end());
return length;
    }
};
```

### 2\. 我的原始思路

遍历数组：

- 遇到等于 `val` 的数，把它改成一个大数 `100`（标记无效）

- 遇到不等于 `val` 的数，计数`length++`

- 最后排序，把大数全部挤到后面

- 返回有效数字个数

### 3\. 该思路存在的所有BUG（重点）

**缺陷1：投机取巧，不通用，存在致命漏洞**

强行用 `100` 当做无效标记，一旦题目数组本身包含 `100`，会把原本合法的元素错误标记成无效，直接答案错误。

只是本题数据范围凑巧没有100，所以能过，**换题直接炸裂**。

**缺陷2：多此一举，时间复杂度极差**

题目根本不需要有序，你额外写了`sort`，复杂度变成 $O(n\log n)$。

标准双指针只需 $O(n)$，效率碾压。

**缺陷3：最初版本还有严重运行错误**

- 一开始 `nums[i]`，`i = nums.size()` 造成**数组越界**

- while 循环不更新 j，造成**死循环超时**

**总结：标记\+排序属于歪路子，绝对不推荐作为正式解法**

## 三、正确标准解法（同向双指针 最优解）

### 1\. 算法思想（核心背诵）

定义两个指针：

- **快指针 i**：遍历所有元素，负责**寻找合法元素**

- **慢指针 j**：负责**存储合法元素的位置**

规则：

只要 `nums[i]` 不等于删除值 `val`，就把它覆盖到 `nums[j]`，然后 j 往后走。

最终 `j` 的数值 = 有效元素个数，即为答案。

### 2\. 完整AC代码

```Plain Text
class Solution {
public:
    int removeElement(vector<int>& nums, int val) {
        int j = 0;
        for(int i = 0; i < nums.size(); i++)
        {
            // 找到合法元素，存入慢指针位置
            if(nums[i] != val)
            {
                nums[j++] = nums[i];
            }
        }
        return j;
    }
};
```

## 四、算法复杂度

- 时间复杂度：$O(n)$ 只遍历一次数组

- 空间复杂度：$O(1)$ 纯原地修改，零额外空间

## 五、最终对比总结（必背）

|对比项|我的错误写法（标记排序）|标准双指针写法|
|---|---|---|
|通用性|差，依赖特殊魔数|极强，所有数据通用|
|时间复杂度|$O(n\log n)$（慢）|$O(n)$（最优）|
|是否符合题意|投机取巧，不规范|题目标准解法|
|稳定性|容易出错|零坑、可直接背诵|

## 六、一句话口诀

**快指针找合法数，慢指针负责存答案，一遍遍历原地去重。**
